## Design implications (decided)
1. Full 1382-tool catalog is loadable and fast, but must sit behind **BM25SearchTransform** (default listing) with **CodeMode** as a second discovery surface, and curated "golden" tools pinned via `always_visible`.
2. Auth = **MultiAuth**: (a) `JWTVerifier(jwks_uri=https://api.telnyx.com/v2/oauth/jwks, issuer=https://api.telnyx.com, algorithm=ES256)` wrapped in `RemoteAuthProvider(authorization_servers=[https://api.telnyx.com], scopes_supported=<32 scopes>)` so MCP clients do real Telnyx PKCE+DCR; (b) a bearer-API-key verifier (`KEY...` prefix → validate by calling `/v2/balance` or `/v2/oauth/introspect`, cache) for single-tenant agents. The **verified token/key is forwarded to Telnyx** via a custom `httpx.Auth` reading `get_access_token()` — never a server-wide static key in production (dev mode may use env key).
3. Scope-aware authorization: map each OpenAPI tag → Telnyx scope family (voice/messaging/numbers/…) + method → read/write; enforce with `require_scopes` in `mcp_component_fn` and produce `InsufficientScopeError` step-up.
4. Route maps: `x-hidden` → EXCLUDE; x402/wss server ops → EXCLUDE (or separate namespace); `deprecated` → tag `deprecated` + Visibility off; GET without path params on stable read endpoints stays TOOL (client compat) but selected "reference data" GETs (e.g. `/available_phone_numbers`, `/balance`, `/ai/models`) ALSO exposed as `RESOURCE`/`RESOURCE_TEMPLATE` via a second provider instance with different maps + Namespace to avoid dup.
5. `mcp_component_fn` sets `ToolAnnotations` (readOnly/destructive/idempotent/openWorld from method), `meta.telnyx = {method, path, latency_category, endpoint_cost, scope}`, human titles from summary, and rewrites pagination param descriptions.
6. Custom (hand-written) layer on top: webhook signature verification (Ed25519, `telnyx-signature-ed25519`/`telnyx-timestamp`), auto-paginating `*_all` helpers, background-task wrappers (`task=True`) for porting orders / number orders / bulk SMS / call recordings, call-control workflow prompts, elicitation-gated destructive ops (delete number, port-out, release), Prefab apps (number inventory dashboard, messaging analytics, call detail records, balance/usage), skills provider serving the 200+ `telnyx-*` SKILL.md folders, completions for E.164 numbers / connection ids / assistant ids, resource templates `telnyx://numbers/{id}`, `telnyx://webhooks/{event}` (from spec `webhooks` block), OpenTelemetry, Redis-backed sessions/tasks/event-store/cache in prod with memory fallback.
