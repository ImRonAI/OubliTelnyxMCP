# Documentation Guidelines

Work here; inherit root guidance. Own source provenance, verified architecture and agent reference navigation. Do not edit application APIs through prose or claim future paths/tests/commands are already implemented.

`docs/reference/SOURCE_INDEX.md` records source URL, release/commit, observation time and SHA-256. Preserve official snapshot contents; put local interpretation/decisions in `docs/architecture`, not inside vendor text. JSON pointers and version-bound `.d.ts`/schema snippets provide types/props; do not reconstruct them from memory.

The original root HTML/source-plan are historical planning artifacts until updated with VERIFIED_DECISIONS. Research fixtures/logs are evidence, not production package manifests. Live docs may be ahead of the installed release; the matching installed public API outranks an obsolete field example. Record incompatibilities rather than papering them over. Avoid duplicated canonical schema copies drifting independently; preserve root originals but select one documented runtime/reference source.

## Assigned directory
Project target: `docs/architecture`. Change into this directory before development. This copy is a planning template; the project scaffold is not installed until the worker applies it.
